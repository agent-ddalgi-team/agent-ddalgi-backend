# 프로젝트 아이디어 — 회사소개서 초안 도우미

## 1. 어떤 프로젝트인가요?

회사 자료를 바탕으로 AI가 회사소개서 초안을 만들고, 사용자가 내용을 확인하고 수정한 뒤 파일로 내려받는 서비스입니다.

기존 README의 **거산케미칼 회사소개서 초안 도우미**를 출발점으로 삼습니다.

회사소개서를 만들 때 반복되는 다음 작업을 줄이는 것이 목적입니다.

- 여러 파일에서 회사 정보와 사진 찾기
- 소개 목적에 맞게 내용을 골라 문장으로 정리하기
- 숫자·인증·사업 설명이 원자료와 일치하는지 확인하기
- 수정한 내용을 문서 파일로 정리하기

AI는 자료 정리와 작성을 돕고, 최종 내용은 사용자가 확인하고 승인합니다.

## 2. 누가 사용하나요?

**주요 사용자는 회사소개서를 작성하거나 갱신하는 회사 담당자입니다.**

| 사용자 예시 | 필요한 도움 |
|---|---|
| 영업 담당자 | 거래처에 맞게 회사와 주요 사업을 소개하고 싶다. |
| 기획·관리 담당자 | 여러 자료를 정리해 기존 소개서를 갱신하고 싶다. |
| 직접 소개서를 작성하는 대표 | 문서 작성 경험이 적어도 초안부터 시작하고 싶다. |

위 직무는 기존 문서의 ‘회사 문서 작성 담당자’를 구체화한 예시입니다. 초기에는 한 회사의 자료와 실제 작성 업무를 중심으로 확인합니다.

## 3. 핵심 기능 — MVP

MVP는 사용자가 핵심 과정을 끝까지 이용할 수 있는 최소한의 첫 버전입니다.

**자료 선택 → 작성 조건 입력 → 자료 점검 → 초안 작성·수정 → 확인·승인 → 다운로드**

| 기능 | 첫 버전에서 할 일 |
|---|---|
| 자료 준비 | 사용할 자료를 선택하거나 업로드하고, 파일별 읽기 성공·실패를 표시한다. |
| 작성 조건 입력 | 소개 목적, 강조할 내용, 목표 분량을 입력한다. |
| 자료 점검 | 회사명·주요 사업 등 필요한 내용과 자료 간 차이를 확인하고, 부족한 자료를 안내한다. |
| 초안 생성 | 선택한 자료를 바탕으로 제목·본문·사진을 구성하고, 내용의 출처를 연결한다. 사진이 없어도 글 중심으로 작성한다. |
| 수정·저장 | 사용자가 직접 내용을 고치거나 선택한 문단의 AI 수정안을 요청한다. 수정안은 사용자가 적용해야 반영한다. |
| 검증·승인·출력 | 원자료와 다른 내용, 필수 내용 누락, 문서 배치 문제를 확인한다. 문제를 해결하고 최종 승인한 문서를 다운로드한다. |

기존 파일 읽기 기능을 재사용합니다. 현재 지원 형식은 TXT·MD·텍스트 PDF·DOCX·PPTX·JPG·PNG입니다. 스캔 문서나 사진 속 글자를 자동으로 읽는 OCR은 포함하지 않습니다.

## 4. 2개월을 위한 범위 조정 제안

아래는 **승인이 필요한 제안**입니다. 기존 요구사항을 이미 변경했다는 뜻은 아닙니다.

2026-09-27 개발 문서 정리 기준으로 현재 계획은 **PDF와 DOCX 모두, 목표 1·4·6·8·10쪽, 사진 후보 기능**을 유지합니다. 아래 축소안을 채택할지는 별도로 결정합니다. 확정·미정 사항은 [plan.md 4절](../plan.md)에서 관리합니다.

| 항목 | 제안 | 이유 |
|---|---|---|
| 문서 서식 | 기본 서식 1종으로 시작 | 서식마다 글 넘침과 사진 배치를 확인하는 부담을 줄인다. |
| 목표 분량 | 1쪽·6쪽을 먼저 지원하고 4·8·10쪽은 후속으로 진행 | 기존 Agent 작업에도 1쪽·6쪽부터 확인하는 순서가 있다. |
| 사진 기능 | 업로드한 사진의 직접 선택·교체부터 구현하고 AI 사진 추천은 후속으로 진행 | 사진 표시와 배치를 먼저 완성하고, 추천 품질 확인은 이후에 진행한다. |
| 출력 형식 | PDF를 먼저 완성하고 DOCX는 후속으로 진행 | 두 형식의 한글·사진·쪽 나눔을 동시에 맞추는 부담을 줄인다. |

**DOCX 다운로드가 첫 사용자에게 꼭 필요하다면 출력 우선순위는 다시 정해야 합니다.** 현재 원래 계획에는 PDF와 DOCX가 모두 포함되어 있습니다.

기존 계획대로 자유로운 도형 편집, 실시간 공동 편집, PPT 출력, 외부 사진 수집, AI 이미지 생성, OCR은 첫 버전에 추가하지 않습니다.

## 5. 범위 조정을 승인할 경우의 8주 진행안

기존 코드를 재사용하고 위 범위 조정을 승인한다는 전제의 목표 일정입니다. 현재 전체 범위의 확정 일정은 아니며, 실제 작업 가능 시간과 별도 프론트 개발 진행에 따라 조정합니다. 전체 범위를 유지할 때의 개발 순서는 [plan.md 8절](../plan.md)을 따릅니다.

| 기간 | 목표 |
|---|---|
| 1주차 | 기존 코드 실행·이해, 범위 확정, 시험 자료 준비, 한글·사진이 들어간 PDF 출력 방식 확인 |
| 2~3주차 | 자료 점검과 실제 AI 초안 생성 연결, 자료 선택 화면 연결 |
| 4~5주차 | 문서 편집·저장, AI 수정안 적용, 사진 선택, 내용 검증 연결 |
| 6주차 | 최종 승인·PDF 다운로드, 세션 종료와 임시 자료 정리 연결 |
| 7~8주차 | 전체 화면과 서버 연결 확인, 오류 수정, 사용자 시험과 사용 안내 정리 |

프론트 화면은 기존 계획대로 별도 저장소에서 개발합니다.

## 6. 범위 조정안의 완료 기준

아래는 4절의 PDF 우선 제안을 채택할 때의 기준입니다. 현재 전체 계획의 완료 기준에는 편집 가능한 DOCX와 선택한 형식의 배치 검사도 포함됩니다([prd.md BR-09·BR-10](../prd.md)).

- 자료 선택부터 승인·다운로드까지 실제 화면에서 진행할 수 있다.
- 실제 AI가 작성한 주요 내용의 출처를 확인할 수 있다.
- 자료에 없는 회사 사실·수치·인증을 임의로 채우지 않고 부족하거나 충돌하는 내용을 표시한다.
- 사용자가 적용하지 않은 AI 수정안은 현재 문서를 바꾸지 않는다.
- 승인 후 문서를 수정하면 다시 확인하고 승인해야 한다.
- 내려받은 PDF에서 한글·사진이 정상 표시되고 본문이 잘리지 않는다.
- 다른 사용자의 작업 자료에 접근할 수 없고, 종료·만료된 작업의 임시 자료를 정리한다.
- 출력에 실패해도 저장된 문서를 유지하고 출력만 다시 시도한다.

## 7. 현재 출발점과 참고 문서

세션·파일 읽기·문서 편집에 더해 등록 자료 조회·CLI 적재·선택 자료 전달, 검증 Job·결과 저장·승인 연결이 구현되어 있습니다. AI는 mock, 즉 개발용 가짜 응답으로 연결되어 있으며 실제 LLM 의미 검증은 아직 연결되지 않았습니다.

- **문서 조회:** 현재 문서·입력 버전의 검증 결과와 유효한 승인 기록이 있으면 실제 값을 반환하고, 해당 결과가 없을 때만 `null`입니다.
- **PDF:** 배치 검사 → 미리보기 → 승인 → Export → 다운로드가 구현되어 있으며 가짜 자료를 사용한 실서버 검증 기록이 있습니다. 실제 회사 자료의 생성 품질과 PDF 전체 흐름까지 검증한 것은 아닙니다. 기존 Windows 성공 기록과 현재 Mac의 PDF 시간 초과는 구분합니다.
- **자료 정리:** BE-09의 세션 종료·만료, 서버 저장 내용 제거, 폴더 삭제와 정리 재시도는 구현되어 있습니다. 실제 LangGraph 체크포인트 정리 연결은 남아 있습니다.
- **남은 작업:** DOCX 승인·Export·다운로드, 실제 Agent·프론트 연결, 체크포인트 정리 연결, 새 경고 확인 정책의 승인 연결입니다. DOCX 파일 생성과 PDF 기준 미리보기는 있으나 DOCX 배치 검증이 끝나지 않아 승인·출력 경로는 차단됩니다.

기존 서버의 버전 검사와 최종 사용자 승인은 이미 동작합니다. 허용 경고의 확인 기록·관련 변경 후 재확인 기반도 있으며, D-07에 따른 확인 의무를 승인 조건에 연결하려면 확인 대상·기록 규격·재확인 조건과 `DEMO_VALUE` 적용 범위를 먼저 맞춰야 합니다. 이번에는 문서 설명만 정정하며 해당 정책 구현은 후속 작업입니다.
