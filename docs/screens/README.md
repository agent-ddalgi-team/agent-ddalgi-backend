# 회사소개서 도우미 화면 설계 기준

기준일: 2026-09-27 · 문서 v1.2

화면을 구현하거나 수정·점검할 때 함께 읽는 참고 문서다. 자료 선택부터 승인·출력까지의 배치와 사용자 행동을 정리했다. 화면 ID인 S01~S03과 상태 ID인 E01~E10을 사용하면 변경할 위치를 정확히 지정할 수 있다.

**확인 상태:** 이 문서의 생성은 사용자 승인을 받았다. 실제 Stitch 결과 이미지의 최종 승인 여부, 프론트 화면 구현과 버튼의 서버 연결은 이번 문서 작성에서 확인하지 않았다. 아래 확인 목록은 아직 수행하지 않은 점검 기준이다.

## 1. 자료의 출처와 관리 범위

| 자료 | 이번 문서에서 사용한 내용 | 보관·확인 상태 |

| [공통 계약](../../contracts.md) 7.5절 | E01~E10과 현재 데이터·오류의 연결 | API 원본. 계약 1.1, 데이터 스키마 1.0 기준으로 대조 |

화면별 핵심 설명은 이 파일만으로 읽을 수 있다. 세부 API 규격은 공통 계약을, 제품 결정은 [개발 계획](../../plan.md) 4절, 미정사항과 결정 시점은 4.1절을 따른다. 화면 제안과 계약이 다르면 차이를 정리하고 관련 담당과 맞춘다.

실제 프론트 코드는 별도 저장소에서 관리한다. 프론트 설계 원본의 저장소·파일 경로와 실제 Stitch 결과 파일은 아직 이 문서에 연결되지 않았다. 자료를 등록할 때 원본 위치·버전·기준일·승인 여부를 함께 적는다.

구현 상태는 작업할 브랜치의 코드와 [백엔드 작업 기록](../../task_backend.md), [Agent 작업 기록](../../task_agent.md)에서 확인한다. 작성 시점의 확인 브랜치는 `chore/shared-ai-setup`이며 다른 브랜치의 후속 구현 상태를 이 문서만으로 판단하지 않는다.

## 3. 공통 화면 기준

- **시작:** 로그인·회원가입 화면 없이 S01 자료 선택부터 시작한다. 로그인은 현재 MVP에서 제외하며 소개서 생성·편집·출력 완성 후 별도 검토한다(plan D-08). 세션 자료의 접근 보호와 만료 안내는 유지한다.
- **작업 흐름:** S01 자료 선택·사전 확인 → S02 초안 편집 → S03 승인·출력. 이전 단계로 돌아가 바꾼 내용은 최신 입력·문서 기준으로 다시 확인한다.
- **데스크톱 중심:** 1600px을 기준으로 설계하고 1440px·1280px에서도 주요 작업을 유지한다. 공간이 부족하면 AI 보조 패널을 접거나 필요할 때 여는 방식으로 표시한다.
- **상태 안내:** 선택됨·읽는 중·저장 중·세션 내 저장 완료·확인 필요·실패를 문구와 아이콘으로 함께 표시한다. 사용할 수 없는 버튼에는 이유와 다음 행동을 보여준다.
- **예시 표시:** 8쪽·사진 3개·사업군 4개·99.4%는 시연 예시다. 실제 페이지·사진 후보·문제 목록은 응답 데이터에 맞춘다. 회사의 인증·납기·실적을 예시로 만들어 확정하지 않는다.
- **편집 범위:** 페이지·블록 단위 편집을 사용한다. 자유 좌표·회전·복잡한 도형 편집은 기본 범위에서 제외한다.
- **진행 표시:** 실제 진행률이 없으면 작업 단계와 안내 문구를 보여준다. 버튼 연타 방지와 서버의 중복 요청 방지를 함께 연결한다.
- **사용자 문구:** 버전 번호·DB·AI 도구 이름 같은 내부 구현명 대신 사용자가 해야 할 행동을 설명한다. 이 문서의 기술 용어를 화면 문구에 그대로 노출하지 않는다.

## 4. 화면별 구성과 동작

### S01 — 자료 선택·사전 확인

**목적:** 어떤 자료로 어떤 소개서를 만들지 정하고, 읽기 결과와 보완 내용을 확인한다.

| 영역 | 표시할 내용 | 사용자 행동·조건 |
|---|---|---|
| 왼쪽 작성 설정 | 사용 목적, 강조 내용, 작성 방향, 목표 페이지, 사진 비중 | 방향은 균형형·품질/공정 중심·고객 대응 중심. 목표는 1·4·6·8·10쪽, 사진은 없음·균형·많이 중 선택 |
| 가운데 자료 | 등록 자료·이번 세션 첨부 구분, 선택 체크, 파일 종류·이름·읽기 상태·경고 | 파일 업로드와 사용할 자료 선택을 구분. 선택 해제가 등록 원본 삭제로 이어지지 않음 |
| 오른쪽 사전 점검 | 사용 가능한 근거, 부족·충돌 내용, 추천 쪽수와 이유, 보완 방법 | ‘자료 점검하기’ 후 결과를 확인. 추천만으로 사용자의 설정을 자동 변경하지 않음 |
| 다음 단계 | 점검 결과 확인과 ‘확인하고 초안 만들기’ | 최신 입력의 점검 결과, 사용할 텍스트 근거, 사용자 명시적 확인이 모두 필요 |

- A/B/C 방향 표시는 작성 방향 선택이다. 초안 세 개를 동시에 생성하는 기능으로 만들지 않는다.
- 읽기 상태는 대기·읽는 중·완료·일부 읽기·실패를 구분한다. 스캔 이미지는 읽기 경고로 표시한다. OCR은 기본 범위에서 제외한다.
- 파일 지원은 TXT·MD·텍스트 PDF·DOCX·PPTX·JPG/PNG 기준이다. 사진을 표시할 수 있어도 사진 속 글자를 읽었다고 표시하지 않는다. 문서 내부 사진 추출 범위는 별도 합의 대상이다.
- 현재 개발 제한은 파일당 10MB·세션당 10개다. 실제 연결에서는 서버 설정과 표시값을 맞춘다. 제한값 전달과 원문/추출문 보기 규격은 계약의 합의 항목을 확인한다.
- 텍스트 근거가 없으면 생성 버튼을 막고 보완 방법을 안내한다(E01). 일부 읽기는 읽지 못한 위치를 보여주고 최신 점검 결과에 따라 진행 여부를 안내한다(E02).
- 인증·사진 추천은 자동으로 필수 조건이 되지 않는다. 근거 수를 표시하면 자료 수·읽은 구간 수·사실 수 중 무엇인지 명시한다.
- 점검 완료와 사용자 확인은 구분한다. 서버가 생성 가능하다고 반환해도 사용자가 확인하기 전 초안을 자동 생성하지 않는다.

**표시할 상태:** 초기 빈 화면 → 자료 선택·읽기 → 사전 점검 중 → 결과 확인 전 → 사용자 확인 → 초안 생성 중. 읽기 실패·자료 보완 필요 상태에서는 다음 행동을 안내한다.

### S02 — 초안 편집

**목적:** 목차와 페이지를 보며 직접 수정하고, 선택한 부분의 AI 수정안을 비교·적용한다.

| 영역 | 표시할 내용 | 사용자 행동·조건 |
|---|---|---|
| 왼쪽 목차 | 실제 문서의 페이지·블록 목록, 선택 표시, 순서 이동·페이지 추가 | 목차 선택 시 오른쪽 해당 위치로 이동. 페이지에서 선택한 항목도 목차에 반영 |
| 오른쪽 페이지 | A4 비율의 편집 영역, 제목·본문·목록·사진, 선택 블록 도구막대 | 문구 직접 편집, 허용된 블록 추가·삭제·이동, 사진 교체. 목차와 같은 페이지/블록 ID 사용 |
| 필요할 때 여는 AI 패널 | 선택 범위, 요청 입력, 기존/제안 비교, 제안 이유·근거 | 요청 → 비교 → 사용자 적용. 적용·다시 요청·닫기 동작을 구분 |
| 사진 선택 | 사용 가능한 사진 후보, 추가 첨부, 후보 없음 안내 | 사용자가 후보를 고르고 적용. 서버의 버전 검사·적용 성공 후 문서 갱신 |
| 근거·문제 안내 | 연결된 원자료·위치·짧은 원문, 확인이 필요한 주장 | 원자료를 확인하고 내용을 수정하거나 해당 주장을 제외. 필수 내용 제외로 승인 조건을 우회하지 않음 |

- 목차의 8쪽 구성은 예시다. 페이지 목록은 실제 문서 데이터를 따르며 실제 출력 쪽수와 구분한다.
- 페이지는 문장을 클릭해 편집할 수 있어야 한다. A4 비율의 편집 화면만으로 PDF/DOCX 출력 배치가 검증되었다고 판단하지 않는다.
- AI 제안은 명시적 적용 전 문서를 자동 변경하지 않는다. 사용자는 AI 요청 중에도 직접 편집할 수 있다. 기준 문서·입력이 달라진 제안은 적용을 막고 다시 요청하도록 안내한다(E04·E06).
- 사진 후보 수는 반환된 목록을 따른다. 후보가 없으면 추가 첨부 또는 글 중심 구성을 안내한다(E03). 사진 비중이 ‘없음’이면 자동 배치하지 않는다. 실제 회사 사진을 AI로 만들어 대체하지 않는다.
- 근거 아이콘은 기존 블록의 관련 정보다. 임의 신뢰도 점수를 붙이지 않으며 근거가 있다는 이유로 제안 전체의 진위를 보증하지 않는다.
- 새 자료를 실제로 선택하거나 사용 중인 자료가 바뀌면 기존 편집 보존 → 재점검 → 사용자 확인 → 문장·사진·근거 영향 확인 → 수정안 적용 또는 현 내용 유지 → 최신 입력 연결 → 필요한 재검증으로 이어진다(E05). 세부 연결은 [제품 요구사항 BR-05](../../prd.md)과 계약 C-05를 따른다.
- ‘내용 확인 후 승인·출력으로’ 이동할 때 저장되지 않은 변경과 재검사가 필요한 내용을 안내한다.

### S03 — 승인·출력

**목적:** 최종 내용과 선택한 파일 형식의 배치를 확인한 뒤 승인하고 다운로드한다.

| 영역 | 표시할 내용 | 사용자 행동·조건 |
|---|---|---|
| 문서 검토 | 페이지 목록·본문·사진, 선택 형식의 출력 미리보기 | 페이지 이동, 해당 페이지를 S02에서 수정. 출력 미리보기의 조회·완료 기준은 계약 C-09 확인 |
| 형식 선택 | PDF: 배포·인쇄용 / DOCX: Word에서 추가 편집 | 형식을 바꾸면 해당 형식으로 배치 검사·승인을 다시 진행. 본문이 같으면 초안 재생성 없음 |
| 확인 결과 | 회사명·주요 사업/공정, 포함된 수치·조건·인증 근거, 사진/캡션, 글 넘침·사진 배치 | 문제의 이유·위치와 수정 행동을 표시. 인증은 포함한 주장에 따라 확인하고 사진 없음은 허용 |
| 최종 승인 | 미리보기·내용 확인, 형식에 맞는 승인 버튼 | ‘승인하고 PDF 만들기’ 또는 ‘승인하고 DOCX 만들기’. 사용자 동의와 서버 승인 조건을 함께 충족해야 실행 |
| 파일 생성·다운로드 | 생성 중·성공·실패, 해당 형식 다운로드 | 실제 파일이 준비된 뒤 다운로드 제공. 실패하면 유효한 승인본의 출력만 재시도 |

**승인 버튼:** 최신 저장 문서·입력·사전 확인·내용 검증·선택 형식의 배치 결과가 필요하다. 유효한 소유 세션과 사진·템플릿 등 승인 대상의 일치도 서버가 확인한다. 검사 중·실패·오래된 결과·미해결 필수 문제(blocker)가 있으면 승인할 수 없다. 최종 동의 체크만으로 통과시키지 않는다. 경고의 승인 정책은 PRD BR-08/09와 plan D-07로 확정했으며, 상태·요청·기록 연결은 계약 C-08/C-09에서 구체화한다.

- **필수 문제와 경고:** 사실·수치·필수 내용의 정확성 또는 출력 이용에 영향을 주는 문제는 해결 전 승인 차단한다. 사진 부족·표현 반복처럼 영향 없는 경고만 남으면, 사용자가 내용을 확인하고 나머지 승인 조건을 충족했을 때 승인할 수 있다. 미확인 경고는 확인을 요청한다.
- **확인 기록:** 확인 버튼으로 필수 문제를 경고로 낮추지 않는다. 경고 확인을 해당 문제·문서/입력 버전에 연결하고, 관련 문장·사진·근거가 바뀌면 다시 확인하도록 표시한다. 무관한 변경의 확인은 서버가 현재 버전에서 유효성을 확인한 경우 유지할 수 있다.
- **차단 유지:** 사진 부족 경고를 확인해도 깨진 사진·남은 사진 자리는 해결해야 한다. `needs_review`라는 이름이나 최종 동의 체크만으로 승인 가능 상태를 만들지 않는다.

- 승인 후 문구·사진·자료가 바뀌면 필요한 재검사와 재승인을 안내한다.
- 승인, 파일 생성, 다운로드 준비를 각각 표시한다. 출력 실패·재다운로드에 AI 초안을 다시 호출하지 않는다(E08).
- DOCX는 글·사진을 편집할 수 있어야 한다. 사용하는 프로그램·폰트에 따라 PDF와 쪽 나눔이 달라질 수 있다.
- **보기 방식 제안:** 카드형은 기존 제목·본문 일부·사진 유무를, 3단 분할은 목차·페이지·확인 정보를, 단일 페이지는 한 쪽의 내용을 보여준다. 첫 버전에 포함할 보기 방식의 우선순위는 합의 대기다. 보기 전환만으로 AI 요약을 새로 생성하지 않는다.

## 5. 예외 상태와 돌아갈 곳

E01~E10은 화면 상태를 지칭하는 이름이다. 실제 데이터·오류 연결은 [공통 계약](../../contracts.md) 7.5절을 따른다.

| ID | 보여줄 상황 | 다음 행동 |
|---|---|---|
| E01 | 사용할 텍스트 근거 없음 | S01에서 읽을 수 있는 텍스트 자료 추가, 다시 점검·확인 |
| E02 | 일부만 읽음 | 읽지 못한 위치·보완 방법 확인, 최신 점검 결과에 따라 진행 |
| E03 | 사진 후보 선택·부족 | 실제 후보 선택·적용, 추가 첨부 또는 글 중심 유지 |
| E04 | AI 수정안 대기·확인 | 단계 안내 후 비교·적용·다시 요청·닫기. 적용 전 자동 변경 없음 |
| E05 | 편집 중 선택 자료 변경 | S02의 편집 보존·재점검·영향 확인 절차로 복귀 |
| E06 | 수정안 기준 버전 충돌 | 오래된 제안 적용 차단, 최신 문서로 다시 요청 |
| E07 | 필수 문제 미해결 | 승인 차단 이유와 해결 위치 표시. 확인으로 경고로 낮추지 않음. 허용 경고의 확인·재확인은 S03 기준을 따름 |
| E08 | 출력 실패 | 세션·승인·형식 유효성 확인 후 같은 승인본의 출력 재시도 |
| E09 | 세션 만료 예정 | 서버 만료 시각에 따른 남은 시간 안내 |
| E10 | 세션 종료·만료 | 접근 종료와 새 작업 안내, 삭제 진행 상태 구분 |

초기 브리프의 E11(작업 실패·중복 클릭)은 3절 공통 진행 표시에, E12(형식 변경·승인 무효화)는 S03에 포함했다. 별도 서버 오류 코드로 추가하지 않는다.

**세션 안내:** 현재 개발 설정은 무활동 120분 또는 생성 후 24시간 중 빠른 때 만료다. GET 조회·작업 폴링은 연장하지 않는다. 저장 완료는 현재 세션 안의 저장이며 영구 보관을 뜻하지 않는다. 서버 접근 차단과 실제 삭제 완료를 구분하고, 이미 사용자 기기에 내려받은 파일은 남는다고 안내한다. 10분 전 알림·명시적 연장·다음 날 이어서 편집은 합의 대기다.

## 6. 아직 정해야 할 사항

제품 결정과 미정사항의 기한은 [개발 계획](../../plan.md) 4~4.1절에서 관리한다. 관련 화면·기능에 착수하기 전에 결정하고, 추가 제안은 채택 전 구현 범위에 넣지 않는다.

- 승인 화면의 카드형·3단 분할·단일 페이지 보기 중 첫 버전 우선순위.
- 만료 예고 시점과 명시적 세션 연장, 장기 보관·다음 날 편집.
- 별도 AI 페이지 요약, 현재 블록·사실 근거보다 세밀한 문장별 출처.
- 별도 결재자에게 승인을 요청하는 계정·역할·업무 절차.
- 원문/추출문·출력 미리보기 조회 방식, 보완 메모, 문서 내부 사진 지원, 페이지 구조 편집의 세부 범위는 기존 계약 C 항목과 개발 계획에서 확인.

기본 범위는 PDF/DOCX와 목표 1·4·6·8·10쪽을 유지한다. [프로젝트 아이디어](../idea.md)의 범위 축소안은 별도 승인 전 제안이다.

## 7. 화면 결과물을 점검할 때

실제 화면을 확인한 뒤 각 항목에 결과와 근거를 남긴다. 화면 시연 성공, 예시 데이터 표시, 실제 서버 연결 성공을 구분한다.

- [ ] S01 → S02 → S03 이동과 이전 단계 수정 후 복귀가 연결된다.
- [ ] 업로드·자료 선택·읽기 상태·세션 보관 안내가 구분된다.
- [ ] 텍스트 근거와 최신 점검·사용자 확인 없이 초안이 생성되지 않는다.
- [ ] 왼쪽 목차와 오른쪽 페이지가 같은 항목을 선택하고 편집한다.
- [ ] AI 제안은 사용자 적용 및 서버 성공 후 반영되며 오래된 제안은 차단된다.
- [ ] 사진 후보가 실제 자료와 연결되고 후보 없음·사진 없음 상태가 동작한다.
- [ ] 선택 자료 변경 후 기존 편집이 보존되고 영향 확인·재검증으로 이어진다.
- [ ] PDF/DOCX 선택에 맞춰 검사·승인·버튼·다운로드가 연결된다.
- [ ] 필수 문제·진행 중·실패·오래된 검사 결과는 동의 체크로 우회되지 않는다.
- [ ] 허용 경고만 남으면 사용자 확인과 나머지 조건 충족 후 승인할 수 있다. 미확인 경고는 확인을 요청한다.
- [ ] 확인 버튼으로 필수 문제를 경고로 낮추지 않으며, 경고 확인 기록은 해당 버전에 연결된다. 관련 내용 변경 후에는 재확인을 요구한다.
- [ ] 출력 실패 시 문서를 유지하고 출력만 재시도한다.
- [ ] 만료 전후의 안내와 접근 종료·새 작업 시작이 구분된다.
- [ ] 예시 수치·미연결 버튼·미정 기능이 실제 완료 기능처럼 표시되지 않는다.
- [ ] 실제 출력 파일의 한글·사진·배치와 DOCX 편집 가능 여부를 확인한다.

점검 결과에는 **화면 ID, 기대 동작, 실제 관찰, 예시/실제 연결 여부, 수정할 파일과 이유**를 적는다. 구현 결과는 해당 저장소의 담당 task 파일에 기록하고, 기준 자체가 바뀔 때 이 문서와 관련 원본을 갱신한다.

## 8. 나중에 요청할 때 사용할 예시

화면 ID와 실제 프론트 저장소·브랜치 또는 화면 자료 위치를 함께 알려주면 범위를 정확히 잡을 수 있다.

**현재 화면 점검**

```text
docs/screens/README.md의 S02와 7절 확인 기준으로 현재 편집 화면을 점검해줘.
프론트 저장소: [경로], 기준 브랜치: [이름], 화면 이미지: [파일 위치].
누락·다른 동작·연결 안 된 버튼·예시 데이터 사용 부분을 표로 정리하고,
수정할 파일과 이유를 알려줘. 수정은 내가 승인한 범위에서 진행해줘.
```

**새 Stitch 결과와 비교**

```text
새 Stitch 결과 [파일 위치]를 docs/screens/README.md의 S01~S03과 비교해줘.
유지할 부분, 달라진 부분, 새 기능 제안을 나눠 설명해줘.
기존 PRD·계약에 미치는 영향과 수정할 파일을 정리한 뒤 승인받아 반영해줘.
```

**승인한 기능 구현**

```text
docs/screens/README.md의 [화면 ID·항목]을 기준으로 승인한 [작업 범위]를 구현해줘.
작업할 저장소: [경로], 역할·작업 ID: [담당과 ID].
현재 코드·계약·담당 task의 상태부터 확인하고 실제 실행 결과와 남은 연결을 기록해줘.
```
